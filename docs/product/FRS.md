## 1. 约定

- `P0`：首发阻断需求；不满足则不能交付内测版。
- `P1`：首发必需但可在对应里程碑后段完成；最终候选仍必须满足。
- 前置条件只描述执行该场景所需状态，不替代需求依赖。
- Given/When/Then 是最低验收条件；非功能门槛见 `NFRS.md`。
- AI 语气、安全和记忆陈述以 `AI-BEHAVIOR.md` 为唯一事实源，视觉交互以 `UX-SPEC.md` 为唯一事实源。

## 2. Onboarding

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-ONB-001 | P0 | 首次启动或引导未完成 | 应用按“欢迎与边界→音乐来源→OpenAI Key→声音→画像→城市与日程→隐私确认”顺序提供可返回的引导，并持久化每步完成状态。 | **Given** 新安装首次启动；**When** 用户完成一步并重启应用；**Then** 返回该步之后首个未完成步骤，且此前输入仍可编辑。 |
| FR-ONB-002 | P0 | 位于音乐来源步骤 | 用户可选本地曲库、Apple Music 陪伴模式或两者；本地源要求至少一个授权目录，Apple Music 选择不要求 MusicKit 登录。 | **Given** 用户未配置来源；**When** 选择“两者”并授权目录；**Then** 两种来源均记录为可配置选项，界面不请求 Apple Developer 凭据。 |
| FR-ONB-003 | P0 | 位于 OpenAI Key 步骤且联网 | 用户输入 BYOK 后必须从 Rust 后端执行最小验证；只保存验证成功的密钥到 Windows Credential Manager，页面仅显示掩码和验证状态。 | **Given** 用户输入有效 Key；**When** 点击“验证”；**Then** 返回成功、保存凭据且 WebView 状态和日志中不存在完整 Key。 |
| FR-ONB-004 | P0 | 位于 OpenAI Key 步骤 | 无效、限流或网络错误必须分类显示；原输入不写入持久化，用户可重试或进入仅本地无 AI 的降级体验。 | **Given** 网络不可达；**When** 用户验证 Key；**Then** 显示网络错误和可继续能力，不把该 Key 标记为已验证。 |
| FR-ONB-005 | P0 | 有已验证 Key且位于声音步骤 | 列出配置 TTS Provider 可用声音，用户可逐个请求短预览并选定默认声音；预览必须由用户点击触发。 | **Given** 声音列表可用；**When** 用户点击一个声音的预览；**Then** 只播放该声音的固定短句，并可将其保存为默认声音。 |
| FR-ONB-006 | P1 | 位于画像步骤 | 收集称呼、偏好时段、音乐倾向、串场密度和陪伴边界；除称呼可留空外均有中性默认值，且不要求敏感信息。 | **Given** 用户不愿填写自由文本；**When** 接受默认值继续；**Then** 引导可完成，画像仅含明确展示的默认项。 |
| FR-ONB-007 | P0 | 音乐来源与隐私选择已完成 | 完成页逐项显示来源、外发数据、原文 30 天保留、通知后确认开播和记忆控制；用户确认后才标记引导完成。 | **Given** 用户到达完成页；**When** 尚未勾选确认；**Then** “完成”不可用；**When** 确认；**Then** 进入 `RADIO` 且不会自动出声。 |

## 3. Radio and program

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-RAD-001 | P0 | 至少一个来源可用 | 用户可从 `RADIO` 明确选择来源并开始节目；任何声音输出都要求本次用户动作或对日程通知的明确确认。 | **Given** 应用后台启动且日程到点；**When** 用户未确认通知；**Then** 不开始节目、不播放 TTS 或音乐。 |
| FR-RAD-002 | P0 | 用户请求开始本地节目 | 系统从真实候选曲目生成经 schema 和曲目 ID 校验的 `Program Plan`；模型不得选择候选集外曲目。 | **Given** 候选集含 A、B、C；**When** 模型返回 A、X；**Then** 拒绝计划中的 X，并按编排降级规则生成只含真实曲目的有效计划。 |
| FR-RAD-003 | P0 | 有有效节目计划 | 节目先显示并可播放一次开场，随后播放音乐；默认每 2–3 首完整曲目后插入一次串场，具体文案遵守 AI 行为规范。 | **Given** 用户开始包含 6 首歌的节目；**When** 没有跳过或错误；**Then** 有一次开场，且任意相邻常规串场之间包含 2 或 3 首完整歌曲。 |
| FR-RAD-004 | P0 | 节目运行中 | `RADIO` 显示真实 Now Playing、来源、进度、节目状态和来源能力允许的播放/暂停/上一首/下一首/进度控制。 | **Given** 当前来源不支持 seek；**When** 页面渲染控制；**Then** 进度可读但 seek 控件不可操作，并给出能力原因。 |
| FR-RAD-005 | P0 | 节目运行中 | 用户可提交“喜欢”“跳过”“少说一点”反馈；事件立即持久化并影响后续候选或本次串场频率，不篡改历史记录。 | **Given** 默认串场密度；**When** 用户点击“少说一点”；**Then** 本节目余下时间按每 4–6 首至多一次串场，并显示已应用状态。 |
| FR-RAD-006 | P0 | 节目运行中 | 用户可结束节目；系统停止 CyberKindred 控制的本地/TTS 音频，记录结束原因，并对第三方会话执行非争抢式释放。 | **Given** Apple Music 正在由用户播放；**When** 用户结束 CyberKindred 节目；**Then** 结束陪伴监听，不擅自停止或改变用户当前的新播放状态。 |
| FR-RAD-007 | P1 | LLM、TTS 或网络能力失败 | 播放器使用确定性本地队列继续；TTS 失败显示同内容文字；错误以一次性内联状态呈现并可重试。 | **Given** 本地节目播放时 TTS 超时；**When** 到达串场点；**Then** 不阻塞下一首超过规定超时，显示串场文字并继续音乐。 |

## 4. Local library

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-LIB-001 | P0 | 用户授权一个可读目录 | 扫描 MP3、FLAC、M4A/MP4、AAC、WAV、OGG，读取可用内嵌标签、时长和封面；不复制原始音频到应用数据目录。 | **Given** 目录含支持、不支持和损坏文件；**When** 扫描完成；**Then** 支持文件成为曲目，其他文件带分类结果且不导致全局失败。 |
| FR-LIB-002 | P0 | 扫描正在运行 | 显示发现数、已处理数、错误数和进度；用户可取消，已完成记录保持一致，下次可增量重扫。 | **Given** 大型目录扫描中；**When** 用户取消；**Then** 新任务停止，已提交曲目可浏览，页面标记扫描未完成。 |
| FR-LIB-003 | P0 | 已配置曲库目录 | 增量扫描以稳定文件身份、修改时间和大小检测新增、修改、移动与删除；已不存在文件不进入候选集。 | **Given** 曲目文件已移动后重扫；**When** 新路径可匹配原文件；**Then** 更新位置并保留合法历史关联，不产生两个可播放副本。 |
| FR-LIB-004 | P1 | 曲目含可查询文本标签且联网 | 仅向 MusicBrainz 发送曲名、艺术家、专辑等文本，遵守限流并缓存结果；低置信匹配不得覆盖原始标签。 | **Given** 返回多个低置信候选；**When** 补全完成；**Then** 保留本地标签，将匹配标为待确认且不上传音频。 |
| FR-LIB-005 | P0 | 曲库已有曲目 | `LIBRARY` 支持按标题、艺术家、专辑文本搜索，按可播放/缺失/匹配状态过滤，并查看原始标签与补全标签来源。 | **Given** 搜索匹配 3 首、其中 1 首缺失；**When** 选择“可播放”；**Then** 只显示 2 首且保留查询文本。 |
| FR-LIB-006 | P0 | 本地节目生成中 | 候选集综合时间、画像、已批准记忆、近期播放、喜欢/跳过和重复限制；确定性规则先筛选，LLM 只重排传入 ID。 | **Given** 某曲目在重复冷却期；**When** 生成候选集；**Then** 除非可播放曲目不足且明确降级，该曲目不会进入候选。 |

## 5. Apple Music companion mode

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-APL-001 | P0 | Windows 可访问 GSMTC | 只识别 Apple Music Windows App 暴露的系统媒体会话，显示连接、无会话、会话失联或能力受限状态；不得操控 Web DOM。 | **Given** Apple Music 未运行但浏览器打开 music.apple.com；**When** 连接；**Then** 不进行 DOM 自动化，并显示启动 Windows App 的连接指引。 |
| FR-APL-002 | P0 | Apple Music 会话存在 | 读取会话实际报告的标题、艺术家、专辑、封面、时间线与播放状态；未知字段显示为未知，不由模型补写事实。 | **Given** 会话只提供标题与艺术家；**When** Now Playing 更新；**Then** 展示两字段，专辑不显示虚构值。 |
| FR-APL-003 | P0 | 会话声明相应能力 | 仅提供运行时允许的播放、暂停、上一首、下一首和进度动作；动作失败后刷新能力与状态，不循环争抢控制。 | **Given** 会话不允许上一首；**When** 页面渲染；**Then** 上一首不可操作；**When** 能力随后出现；**Then** 无需重启即可更新。 |
| FR-APL-004 | P0 | Apple Music 陪伴节目运行中 | 系统只根据实际曲目变化生成本地确定性文字反应，不把 GSMTC 元数据或播放事件发送给 OpenAI，不生成或声称设置 Apple Music 精确队列。 | **Given** 用户在 Apple Music 手动换歌；**When** 系统收到新曲目；**Then** 后续文字反应由本地模板基于新实际曲目生成，OpenAI 请求数为 0，Program Plan 不包含远程曲目队列。 |
| FR-APL-005 | P0 | 到达不含 GSMTC/Apple Music 数据的通用 TTS 段且会话可暂停 | 只有通用问候、时间或用户明确输入等不含 GSMTC 数据的文字可进入 TTS；系统记录会话身份与播放状态，尝试暂停、播放 TTS，且仅在会话未切换、用户未手动改变状态时恢复此前播放。 | **Given** 通用 TTS 期间用户手动保持暂停；**When** TTS 结束；**Then** 不恢复播放；**Given** 会话切换到其他应用；**Then** 不控制新会话；**Given** 文字含 GSMTC 元数据；**Then** 不提交 TTS。 |

## 6. Text chat and feedback

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-CHAT-001 | P0 | `RADIO` 可交互 | 用户可发送文字说明心情、偏好或节目请求；发送前可编辑，发送后按原始对话生命周期保存并进入节目上下文。 | **Given** 用户发送“今天少说一点”；**When** 消息成功处理；**Then** 显示用户消息和简短回应，并应用本次节目频率变化。 |
| FR-CHAT-002 | P0 | 文本请求涉及不可用能力 | 系统明确说明限制并提供当前可行动作；不得声称访问屏幕、麦克风、定位或 Apple Music 内部推荐。 | **Given** 用户要求“看看我正在写什么”；**When** AI 回应；**Then** 说明没有屏幕访问并可邀请用户用文字描述。 |
| FR-CHAT-003 | P1 | 请求正在处理 | 用户可取消尚未完成的 LLM 请求；取消不生成 AI 回复或记忆提案，已发送用户原文仍按数据控制规则可见。 | **Given** 请求尚未完成；**When** 用户取消；**Then** 网络任务停止或结果被丢弃，界面标记已取消且节目继续。 |

## 7. Profile and memory

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-MEM-001 | P0 | 用户打开 `YOU` | 显示画像、偏好趋势、待确认记忆提案、已批准记忆和摘要的不同来源与状态，不将提案混入已批准记忆。 | **Given** 同时有提案与批准记忆；**When** 打开页面；**Then** 两者分区展示并带创建来源和最近使用时间。 |
| FR-MEM-002 | P0 | 产生可长期有用的新推断 | 系统可创建具体、可编辑的 Memory Proposal；用户批准前不得作为长期事实进入后续节目上下文。 | **Given** AI 推断用户喜欢雨天爵士；**When** 用户未处理提案并开始新节目；**Then** 不以确定事实使用该提案。 |
| FR-MEM-003 | P0 | 存在记忆提案 | 用户可批准、编辑后批准或拒绝；拒绝项不再出现，编辑后的最终文本成为唯一批准版本。 | **Given** 提案内容不准确；**When** 用户编辑并批准；**Then** 上下文只使用编辑值，原提案保留最小审计状态而不作为事实。 |
| FR-MEM-004 | P0 | 存在画像或批准记忆 | 用户可编辑、停用、重新启用或删除；删除立即从上下文和导出之外的活动数据中移除，并防止从旧摘要自动复活。 | **Given** 用户删除一条批准记忆；**When** 后续生成节目与摘要；**Then** 不再引用该内容，也不自动重建同义记忆。 |
| FR-MEM-005 | P1 | 存在足够会话历史 | 系统生成长期 Session Summary 以减少原文依赖；摘要标明覆盖时间且可查看、删除，不能包含已删除记忆。 | **Given** 原文到达清理期限；**When** 清理运行；**Then** 保留合规摘要与反馈统计，删除到期原文，并可从 `YOU` 查看摘要。 |

## 8. Schedule and notifications

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-SCH-001 | P0 | 用户打开日程设置 | 用户可创建、编辑、启停和删除按星期与本地时间重复的 Schedule Rule，并显示其 IANA 时区和下一次触发时间。 | **Given** 用户设置周一 07:00；**When** 保存；**Then** 显示当前时区下下一次周一 07:00，重启后保持。 |
| FR-SCH-002 | P0 | 启用规则到点 | Windows 通知提供“开始节目”“稍后提醒”“忽略”；未点击开始不得播放任何声音。 | **Given** 应用关闭或托盘运行且规则到点；**When** 通知出现但无人操作；**Then** 保持静音且记录为待处理/过期。 |
| FR-SCH-003 | P1 | 用户选择稍后提醒 | 提供 10、30、60 分钟延后；同一次触发只保留一个有效延后，不修改原重复规则。 | **Given** 用户先延后 10 分钟再改为 30 分钟；**When** 30 分钟到；**Then** 只出现一次新通知，原规则时间不变。 |
| FR-SCH-004 | P0 | 时区或 DST 发生变化 | 下一次触发按规则保存的时区重新计算；重复/不存在的当地时间采用文档化确定规则并在 UI 显示结果。 | **Given** DST 跳过设定时间；**When** 计算下一触发；**Then** 当天在首个有效当地时间触发一次且不重复。 |

## 9. Weather context

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-WEA-001 | P1 | 用户配置城市且联网 | 用户通过名称搜索并明确选择城市；保存城市名、国家/地区、坐标和时区，不请求设备定位。 | **Given** 搜索返回同名城市；**When** 用户选择其中一个；**Then** 设置显示地区与时区，保存对应坐标且不读取定位权限。 |

## 11. Data control

| ID | Priority | 前置 | 规则 | Given / When / Then |
|---|---|---|---|---|
| FR-DAT-001 | P0 | 存在原始对话 | 原始对话默认在创建 30×24 小时后由启动及每日维护任务清理；清理不延长于“最后查看”或摘要生成时间。 | **Given** 一条原文已超过 30 天；**When** 清理任务成功运行；**Then** 原文不可查询，相关合规摘要和非文本反馈仍可保留。 |
| FR-DAT-002 | P0 | 用户打开数据控制 | 用户可查看每类本地数据、保存位置类别、数量、保留期与可能外发的服务；不显示完整密钥或不必要的绝对音乐路径。 | **Given** 已有对话、记忆和曲库；**When** 打开数据概览；**Then** 分类型显示数量、保留与外发说明。 |
| FR-DAT-003 | P0 | 用户请求导出 | 生成版本化、可读的本地导出，包含画像、批准记忆、提案状态、摘要、对话范围、设置与播放/反馈记录；排除 API Key 和音乐文件。 | **Given** 导出成功；**When** 检查制品；**Then** 有清单与 schema 版本，不含 secret、音频二进制或未授权文件副本。 |
| FR-DAT-004 | P0 | 用户选择删除某类数据 | 按画像/记忆、对话与摘要、播放历史、元数据缓存或曲库索引执行可预览删除；不删除用户原始音乐文件。 | **Given** 用户选择删除曲库索引；**When** 二次确认；**Then** 移除索引和派生数据，原始目录及文件保持不变。 |
| FR-DAT-005 | P0 | 用户请求全部重置 | 二次确认后不可恢复地删除数据库及迁移/恢复备份、缓存、生成音频、应用日志、Credential Manager 中密钥及应用设置，并取消日程/自启动；重启回到首次引导且不删除音乐文件或用户主动保存的导出。 | **Given** 用户输入界面要求的确认并执行；**When** 重置完成后重启；**Then** 显示首次引导，应用目录和凭据中没有可恢复用户数据，授权目录中的音乐与用户主动保存的导出仍存在。 |

## 12. 功能边界验收

满足本规格不意味着可以绕过 `NFRS.md`。尤其是：Apple Music 行为必须始终受实时 capability 约束；记忆提案与批准记忆必须隔离；任何日程、自启动或后台恢复都不得绕过用户确认自动发声；产品不得通过 WebView 直接调用外部 Provider 或持有密钥。
