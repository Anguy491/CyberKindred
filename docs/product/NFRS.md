## 1. 验证基线

除条目另有说明，桌面性能测试使用 Windows 10 22H2 或 Windows 11、4 核 2.0 GHz 以上 CPU、8 GB RAM、SSD、1920×1080@100% 缩放、10,000 首混合格式本地曲库，执行 3 次后取最差结果。网络测试使用 100 Mbps 下行、20 Mbps 上行、40 ms RTT 的受控网络。`P0` 为发布阻断，`P1` 为发布前必须满足但允许在后续里程碑验证。

## 2. Performance

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-PERF-001 | P0 | 已完成引导的冷启动从进程创建到主窗口可交互不超过 5 秒，热启动不超过 3 秒；启动期间不得自动播放。 | 在基线机器各测冷/热启动 10 次，P95 达标且音频捕获为静音。 |
| NFR-PERF-002 | P0 | 10,000 首曲库完整扫描期间 UI 主线程长任务不得超过 100 ms，取消操作在 1 秒内被接受，进度至少每 500 ms 更新一次；完整扫描在 15 分钟内结束。 | 使用固定 10,000 文件 fixture 采集 WebView 性能轨迹、取消延迟和总耗时。 |
| NFR-PERF-003 | P0 | 播放、暂停、下一首、喜欢等本地 UI 操作从输入到视觉确认 P95 不超过 100 ms；从输入到本地音频动作 P95 不超过 300 ms。 | 自动化 200 次操作并对 UI 时间戳与音频/后端事件时间戳求 P95。 |
| NFR-PERF-004 | P0 | Apple Music 会话状态或曲目变化在收到 GSMTC 事件后 2 秒内反映到 UI；能力变化在 2 秒内反映到控件。 | 实机产生各类变化 50 次，至少 49 次在门槛内，余下 1 次不得超过 5 秒。 |
| NFR-PERF-005 | P1 | 空闲托盘状态工作集不超过 250 MB、CPU 5 分钟平均低于 1%；本地播放且无扫描时工作集不超过 500 MB、CPU 平均低于 10%。 | Windows Performance Recorder 采样各场景 10 分钟，记录平均 CPU 和峰值工作集。 |

## 3. Reliability

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-REL-001 | P0 | 连续 30 分钟本地节目不得发生未处理异常、进程退出或超过 2 秒的非预期静音；相邻本地曲目转换成功率至少 99%。 | 运行 100 次固定 30 分钟加速/实时时序测试并分析运行记录与音频探针。 |
| NFR-REL-002 | P0 | 崩溃、断电模拟或强制结束后，下一次启动必须保持数据库可读或进入可恢复模式，且始终处于非自动播放状态。 | 在数据库写入、扫描、节目运行和 TTS 缓存阶段分别终止进程，重启验证 20 轮。 |
| NFR-REL-003 | P0 | 外部 Provider 的超时、429、5xx、无效响应与离线必须被分类；单次 LLM 结构化失败最多重试 1 次，TTS 失败不得自动重复播音，失败不终止本地播放。 | 故障注入覆盖每类错误，断言重试次数、错误分类和本地播放器存活。 |
| NFR-REL-004 | P0 | 休眠/唤醒、默认输出设备改变或 GSMTC 会话消失后 5 秒内进入明确状态；恢复不得控制新的第三方会话或自行发声。 | 在节目各状态执行每类系统变化 20 次，检查状态机、会话身份和音频输出。 |

## 4. Security

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-SEC-001 | P0 | OpenAI Key 等 secret 只存于 Windows Credential Manager；SQLite、前端存储、IPC 响应、崩溃报告、日志和导出中不得出现完整 secret。 | 使用唯一 canary Key 完成全流程后扫描进程可访问持久化文件、日志、IPC fixture 与导出，匹配数必须为 0。 |
| NFR-SEC-002 | P0 | 外部网络请求只能由 Rust 后端发起并使用 HTTPS；生产 CSP 禁止任意远程脚本、WebView 直接 Provider 请求和非白名单连接。 | 静态检查 Tauri capabilities/CSP 与前端网络调用，运行代理捕获所有出站请求并核对域名及 TLS。 |
| NFR-SEC-003 | P0 | 文件访问限定为用户逐项授权的曲库目录与应用专属数据目录；导出目标必须由用户选择，路径遍历与符号链接不得扩大权限。 | 以越界路径、`..`、junction/symlink 和权限变化执行安全集成测试，所有越界操作被拒绝。 |
| NFR-SEC-004 | P0 | 日志默认不记录请求正文、对话正文、API Key、完整本地路径或个人画像；路径最多保留不可逆标识和扩展名，错误栈须脱敏。 | 自动生成包含 canary 的各类数据，运行日志扫描规则，敏感匹配数必须为 0。 |
| NFR-SEC-005 | P1 | 发布候选生产依赖无已知 Critical/High 漏洞；许可证与来源可追溯，构建锁文件无未审查变化。 | 对 Rust/JavaScript 依赖执行锁定的审计工具；Critical/High 数为 0，并人工核对依赖清单差异。 |

## 5. Privacy

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-PRIV-001 | P0 | 首发不采集屏幕、前台应用、麦克风、设备定位或通讯录，不包含遥测/广告 SDK；操作系统权限清单不得声明这些能力。 | 检查 manifest、Tauri capabilities、依赖与运行时系统权限；网络代理中不得出现相关数据。 |
| NFR-PRIV-002 | P0 | 原始对话自创建起最多保留 30×24 小时；维护任务至少每 24 小时及每次启动运行，清理失败必须可见并在下次启动重试。 | 使用可控时钟验证 29 天 23:59 保留、30 天到期删除、失败重试和 DST 不影响绝对保留期。 |
| NFR-PRIV-003 | P0 | 数据导出和分类删除结果必须与 `PRIVACY-DATA-LIFECYCLE.md` 的数据清单逐项一致；全部重置后除用户音乐文件和用户主动保存的导出外无活动用户数据或 secret。 | 播放、聊天、记忆、天气、元数据全流程后执行导出、分类删除和重置，逐项比对数据库、缓存、凭据与任务计划。 |
| NFR-PRIV-004 | P0 | 对外数据最小化：MusicBrainz 不接收音频/路径；Open-Meteo Geocoding 仅在用户主动搜索时接收搜索文字与语言/结果上限，Forecast 只接收所选城市坐标与所需天气参数；OpenAI 只接收生成所需上下文且请求设置 `store: false`；Apple Music 数据保持本机处理。 | 使用本地代理与 provider mock 捕获请求：城市搜索与天气请求分别按白名单断言，其他服务字段白名单外字段数必须为 0。 |
| NFR-PRIV-005 | P0 | Memory Proposal 未批准前不得进入长期上下文；停用/删除记忆在下一次上下文组装前生效，删除内容不得从旧摘要重新生成。 | 契约测试比较批准前后上下文，并进行删除后 20 轮摘要/提案生成回归，复现数为 0。 |

## 6. Accessibility

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-A11Y-001 | P0 | 首次引导、四个主页面、节目控制、记忆操作、设置和数据重置可仅用键盘完成；焦点顺序与视觉顺序一致且无焦点陷阱。 | 依据 `UX-SPEC.md` 键盘路径执行人工和 Playwright 测试，所有路径通过。 |
| NFR-A11Y-002 | P0 | 正文和控件文字对背景对比度至少 4.5:1，大号文字至少 3:1；非文字控件边界/状态至少 3:1，信息不只依赖颜色。 | 对每个 token 组合运行 WCAG 对比检查并用灰度截图检查状态文本/图形。 |
| NFR-A11Y-003 | P0 | 所有交互控件有可访问名称、角色、状态和键盘焦点；Now Playing 与内联错误通过适度 live region 宣告，TTS 不是唯一信息通道。 | 使用 Windows Narrator 完成核心流程并执行 axe 自动检查，严重/高影响违规数为 0。 |
| NFR-A11Y-004 | P1 | 尊重 Windows 减少动画设置；启用时去除非必要过渡，任何闪烁不超过每秒 3 次，控件最小目标尺寸为 44×44 CSS px。 | 开关系统设置后比对动画与尺寸，使用自动化扫描所有可点击元素。 |

## 7. Compatibility

|---|---|---|---|
| NFR-COMPAT-001 | P0 | NSIS x64 安装包支持已更新的 Windows 10 22H2 与 Windows 11；在干净标准用户账户可安装、运行、卸载且不要求管理员权限。 | 两个 OS 的干净 VM 完成安装→首次引导→本地播放→卸载，并验证用户数据处理提示。 |

| NFR-COMPAT-003 | P0 | UI 在 1280×720 至 3840×2160、100%–200% 缩放可操作，无被永久遮挡的关键控件；Apple Music 实机验证使用当前受支持 Windows App，未暴露能力必须安全隐藏。 | 截图矩阵检查所有主状态，并在真实 Apple Music App 对可用能力逐项验收。 |

## 8. Cost control

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-COST-001 | P0 | 日程触发、后台扫描、空闲托盘和 Apple Music 纯监听不得产生付费 Provider 调用；付费调用仅源自用户确认的节目、文字请求、声音预览或显式连接测试。 | 使用计数 mock 运行 24 小时虚拟日程/后台场景，未确认付费调用数必须为 0。 |
| NFR-COST-002 | P1 | 每次 LLM 请求输入预算不超过 24,000 tokens、输出上限不超过 4,000 tokens，候选曲目不超过 200；每段 TTS 文本不超过 500 个 Unicode 字符，并显示本机会话用量计数。 | 边界测试注入超长画像、历史、曲库和文本，断言裁剪优先级、请求参数及 UI 计数。 |

## 9. Maintainability

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-MAINT-001 | P0 | Rust/TypeScript 公共类型与 `docs/contracts/schemas/`、IPC 契约保持一致；每个 schema 合法/边界示例通过、非法示例失败，契约变更必须有版本与 Changelog。 | CI 运行双语言 schema 契约测试和示例验证；不一致或未记录破坏性变更即失败。 |
| NFR-MAINT-002 | P0 | 核心域逻辑行覆盖率至少 80%、分支覆盖率至少 70%；状态机、保留清理、候选约束、secret 边界和 Apple Music 恢复竞态为 100% 场景覆盖。 | CI 生成 Rust/TypeScript 覆盖率报告并执行关键场景清单；任一阈值不足即失败。 |
| NFR-MAINT-003 | P0 | 生产运行路径不得使用未处理 `unwrap`/`expect`、浮动异步任务或未分类错误；所有 `FR/NFR` 必须映射至少一个测试和任务，仓库不得存在未解释占位内容。 | 静态检查、lint、文档 ID/引用检查与 `TRACEABILITY.md` 审计全部通过。 |

## 10. Offline degradation

| ID | Priority | 可判定要求 | 验证方法 |
|---|---|---|---|
| NFR-OFF-001 | P0 | 完全离线时已扫描本地曲库的浏览、确定性队列、播放控制、反馈记录、设置查看、记忆查看/编辑/删除、导出与重置仍可使用。 | 阻断所有网络后执行离线验收矩阵，所列能力通过且无持续错误弹出。 |
| NFR-OFF-002 | P0 | 离线或单 Provider 故障必须按能力独立降级，状态在 2 秒内显示；过期天气不得进入上下文，MusicBrainz 缓存须标记来源/时间，TTS 失败保留文字。 | 分别阻断每个域名并注入过期缓存，检查 UI、Context 和仍可用能力。 |
| NFR-OFF-003 | P1 | 网络恢复后 10 秒内可通过用户动作重试或自动刷新非付费状态；不得自动重放文字请求、TTS 或其他可能计费/出声动作。 | 断网产生各类失败后恢复网络，观察 30 秒并验证只恢复连接状态，显式重试后才发起付费请求。 |

## 11. 发布判定

所有 `P0` 条目必须在目标系统上留有自动化报告或人工证据；所有 `P1` 条目必须在发布候选冻结前通过。任何豁免都属于基线变更，必须记录原因、期限和用户批准，不能通过跳过测试隐式接受。
