## Environment

- Windows 11 Home x64, build `10.0.26200`, Australia/Sydney.
- Rust `1.98.0`, Node `24.19.0`, pnpm `11.16.0`.
- Product checks were hermetic except dependency advisory/index refresh. No live OpenAI, TTS, MusicBrainz, credential, user music, notification, microphone, screen capture or physical audio device was used.
- The representative licensed fixture is repository-owned CC0 test media with one file in each supported format: MP3, FLAC, M4A/AAC, OGG/Vorbis, WAV and AIFF.

## Completed scope

- `TASK-011`–`TASK-019` are `Done`: transactional/cancellable local scan, path-free library UI, metadata enrichment, local playback actor, deterministic candidates/plans, structured Responses provider, bounded speech core, program runner and Radio UI.
- The licensed-fixture vertical integration scans and tags all six formats, builds a deterministic plan containing exactly those six track IDs, emits text-only speech, runs all six tracks in order, exposes control state and reaches an explicit API-025 stop with `Stopping` then `Completed` terminal state.
- Radio loads authoritative API-016/API-018 snapshots and strict API-016–API-025 events. Only the visible “开始节目” user action invokes API-024; startup, reload and provider-unavailable paths neither open audio nor call a paid provider.
- The UI displays source, status, revision, progress, plan and degradation text; `programId` plus revision prevents stale event takeover. Stop and playback controls remain user-driven, and the future M4 text action is visibly disabled.
- OpenAI or TTS failure preserves readable segments and deterministically falls back to the local queue. TTS-disabled tests assert zero speech request, and safe error projections keep secret and absolute paths out of WebView events.
