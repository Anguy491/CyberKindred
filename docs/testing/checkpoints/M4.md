## Completed scope

- `TASK-020` is `Done`: Radio accepts bounded text, Enter/Shift+Enter is explicit, cancellation is terminal, like/skip/less-talk feedback persists immediately, and less-talk suppresses later voice until at least four completed tracks. A provider-unavailable request stores the user turn plus a fixed `local/deterministic` notice without a paid call or proposal.
- `TASK-021` is `Done`: strict Rust/TypeScript contracts and transactional storage implement profile/preferences/trends, proposal provenance, approval/edit/reject, approved/disabled state, optimistic revision checks, deletion tombstones, exact resurrection suppression and approved-memory-only context. Memory projection is capped to 20 rows and 240 characters per row.
- `TASK-022` is `Done`: `YOU` separates profile, trends, proposed/approved/disabled memory and summaries; supports the required mutations; summary deletion prevents cleanup regeneration; raw chat and rejected proposal bodies expire from creation time at 30 days; maintenance runs at startup and every 24 hours with redacted diagnostics and retry on the next run.
- OpenAI Responses chat is stateless (`store:false`), strict-schema, no-tools, bounded and cancellable. Provider output is untrusted data, cannot approve memory or control playback, and sensitive proposal classes are explicitly prohibited and domain checked.
- The final storage regression discovered by the full gate was fixed so a pending current user turn retains its 4,000-character bound while every completed transcript row is historical and capped to 500 characters.

## Actual failures

- The first virtual-time scheduler test paused Tokio before SQLx pool initialization and timed out. This was blocker attempt 1/3; setup now opens/inserts before pausing, resumes before reopen, and focused plus full suites pass.
- The first dependency command used `cargo audit --locked`, which the installed CLI does not support. This was attempt 1/3; the supported `cargo audit` invocation completed with zero vulnerability advisories and 18 allowed warnings.
- A strict Clippy rerun found the now 101-line transactional `persist_chat_result`. This was attempt 1/3; a narrow, documented `too_many_lines` allowance preserves the single atomic transaction, and strict Clippy passes.
- The first final Rust workspace run found that a completed transcript ending in an assistant row was incorrectly treated as corrupt by the new context-bound logic. This was attempt 1/3; the loader now treats only a pending final user row as the untruncated current turn, the focused regression passed, and the exact full suite then passed 250 tests.
- Early security launch attempts supplied a stale working-tree head and were rejected twice. The third bounded attempt established the working-tree review; after the final regression fix, a new exact immutable range scan was completed and is the sole security result cited by this checkpoint.
