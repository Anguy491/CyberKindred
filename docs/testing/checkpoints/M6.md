## Environment

- Rust `1.98.0`, Node `24.19.0`, pnpm `11.16.0`.
- Automated checks were hermetic and did not use a live provider, real credential, user music, physical audio, notification permission mutation, microphone, screen capture or external publication.
- The required real Apple Music Windows App session has not yet been made available for this checkpoint. No result below treats renderer-only or fake-session evidence as a substitute for that path.

## Implemented scope

- `TASK-025` implements the Apple Music Windows App GSMTC source, installation/session states, bounded real fields, runtime capability gates, playback state/revision mapping, session replacement handling and a five-second refresh loop. Discovery now starts only after explicit Apple selection or authoritative restoration of a saved Apple default.
- `TASK-026` implements local deterministic track-aware visible reactions, program lifecycle persistence, generic-only TTS, session/revision/capability interruption tokens, user-override handling and disconnected/reconnected program states. Apple/GSMTC data is structurally absent from Responses and Speech inputs.
- `TASK-028` is `Done`: Settings, masked provider credentials, Apple connection status, tray and per-user autostart are integrated; startup and tray paths remain silent.
- `TASK-027` is reopened as `Blocked`. The final security review disproved its deletion/reset completion claim: category deletion can retain or recreate covered data, Library Index deletion can roll back, export staging can survive cleanup, and full reset lacks an awaited all-producer quiescence barrier.
