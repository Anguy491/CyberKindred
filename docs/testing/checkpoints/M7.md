## Environment and safety boundary

- Windows 11 Home x64 build `10.0.26200`, Australia/Sydney; Rust `1.98.0`, Node `24.19.0`, pnpm `11.16.0`. Fixed `nightly-2026-09-01` was used only for branch coverage; it did not replace the product toolchain.
- All default functional tests were hermetic. Scanner/performance tests used licensed repository fixtures or generated rows in temporary directories; accelerated/virtual radio tests emitted no physical audio and made no network request.
- No real provider, paid API, notification/audio permission change, production install, production uninstall, user-profile reset, signing, upload or external distribution occurred.
- The host is not treated as a disposable standard-user VM. Hyper-V/VirtualBox and suitable Win10/Win11 images were unavailable; QEMU had no test images. User-only device/login/manual steps are `waiting for user`, not retried.

## Coverage hard-gate blocker

| Metric | TypeScript | Rust | Repository | Required | Result |

The Rust/repository figures are the latest completed direct three-package measurement at `0c2d477`: Rust 21,996/29,729 lines and 1,959/3,682 branches; repository 23,399/31,531 lines and 3,493/5,863 branches. The final recovery/release-script follow-up did not justify a fourth unchanged coverage attempt. The exact-candidate TypeScript rerun remained 1,403/1,802 lines and 1,534/2,181 branches.

Blocker fingerprint: `TASK-032 + release coverage + repository aggregate below 80/70`.

1. Attempt 1/3: stable Rust `cargo-llvm-cov` could not produce branch coverage; this established that the product toolchain cannot be silently repurposed for the gate.
2. Attempt 2/3: fixed coverage-only nightly ran, but workspace export contained only the credential helper package because of the known workspace-report behavior; no threshold result was claimed.
3. Attempt 3/3: direct per-package `--no-rustc-wrapper`, serialized runs and exact count aggregation produced the authoritative result above. The tool path is fixed, but the codebase is genuinely below threshold.

The third differentiated attempt produced a valid failed measurement. Further retries without additional tests are prohibited; raising or bypassing the approved threshold is not permitted.

## Reproducibility hard-gate blocker

Blocker fingerprint: `TASK-031 + byte-for-byte reproducibility + Windows PDB/NSIS output mismatch`.

1. Attempt 1/3: two clean worktrees exposed line-ending and long-path cleanup differences; generated asset normalization and validated Git long-path cleanup were added.
2. Attempt 2/3: both worktrees built successfully, proving the harness and source/config inventories, but installer, EXE and PDB hashes differed; path/time sources were isolated.
3. Attempt 3/3: fixed `SOURCE_DATE_EPOCH`, path remapping, MSVC `/Brepro` and disabled incremental output made the main executable identical, but PDB and NSIS installer hashes still differed.

The third differentiated attempt leaves `RISK-025` open. A successful single build or matching main EXE cannot substitute for the required complete artifact inventory. The blocker budget is exhausted; resume needs a new PDB/NSIS nondeterminism diagnosis, not another unchanged pair of builds.
